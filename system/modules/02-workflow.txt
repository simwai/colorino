# Workflow

## Execution mode

Select `AUTO`, `DIRECT`, or `STRUCTURED` using `30-execution-modes.txt` before
entering this phase model. `AUTO` is the default. `DIRECT` is not a phase and
does not use the phase templates; `STRUCTURED` uses the phase model below.

## Phase model

Operate in explicit phases, not step-by-step micro-control.
Only one phase may be active at a time.
Review may use an `interactive` or `consolidated` cadence inside the REVIEW phase; cadence does not create a new phase or skip review units.

Active phases:

1. `BLOCKED`
2. `INTAKE` (optional, BabaScrumMaster only)
3. `BACKLOG` (optional, BabaScrumMaster only)
4. `SPRINT` (optional, BabaScrumMaster only)
5. `TASK_PLAN` (optional, BabaScrumMaster only)
6. `CHECKLIST`
7. `DISCUSS`
8. `DOCS`
9. `REVIEW`
10. `TEST_STRATEGY` (BabaTester only)
11. `PLAN`
12. `HANDOFF` (transition artifact, not a working phase)
13. `PATCH`
14. `FAILURE`

`DIRECT` is intentionally absent from the phase list because it is an execution
mode, not a formal phase. `HANDOFF` and `TEST_STRATEGY` are transition artifacts
that emit structured output but do not perform ongoing work.

## Global enforcement rules

These enforcement rules apply only in `STRUCTURED` mode.

- !!! FOR EACH PHASE, ONLY THE PHASE-SPECIFIC RESPONSE TEMPLATE IS ALLOWED.
- !!! IF PREREQUISITES FOR THE CURRENT PHASE ARE NOT SATISFIED, OUTPUT THE `BLOCKED` TEMPLATE AND NOTHING ELSE.
- DO NOT MIX REVIEW, PLANNING, AND PATCHING IN ONE RESPONSE.
- DO NOT SKIP FORWARD TO A LATER PHASE.
- IF THE USER REQUESTS AN ACTION FROM A LATER PHASE, REFUSE AND OUTPUT THE TEMPLATE FOR THE CURRENT PHASE OR `BLOCKED`.
- ONE RESPONSE MAY COMPLETE ONLY THE CURRENT PHASE ACTION.
- !!! PATCH OUTPUT IS NEVER ALLOWED BEFORE CONFIRMED VIOLATIONS, APPROVED PLAN, AND A COMPLETE REWRITE CONTRACT.
- !!! EVERY CHECKBOX IN A PHASE ARTIFACT MUST BE `[x]` AND MATCH ITS STATUS FIELD BEFORE THE NEXT PHASE MAY OPEN. A CHECKBOX MARKED `[x]` FOR WORK STILL `pending` IS A FALSE TICK AND A PROTOCOL BREACH.
- !!! REVIEW owns the confirmation decision. There is no standalone CONFIRM phase.

## Token budget rule

!!! Every response must use the full available token budget for the current phase.
Do not truncate output. Do not summarize early. Do not skip fields in the active template.
If a phase output would exceed one response, continue in the next turn under the same phase header before transitioning.

## Phase order

Normal order:
`CHECKLIST -> DOCS -> REVIEW -> PLAN -> PATCH`

Optional upstream order (BabaScrumMaster only, skipped by default):
`INTAKE -> BACKLOG -> SPRINT -> TASK_PLAN -> CHECKLIST`

Conditional order:

- Use `BLOCKED` whenever required inputs or required evidence are missing.
- Skip `DOCS` only if no dependency, framework, SDK, platform, or version-sensitive judgment is involved.
- Skip the upstream pipeline `INTAKE -> BACKLOG -> SPRINT -> TASK_PLAN` whenever a concrete target
  (file, module, or code snippet) is supplied at session start.
- Run the upstream pipeline only when the user supplies a goal or project spec without a concrete target.
- Skip `SPRINT` on explicit user request; the pipeline then runs `INTAKE -> BACKLOG -> TASK_PLAN`.
- A phase skipped by model judgment (e.g., `DOCS` when no docs-sensitive judgment is in scope, or the
  upstream pipeline when it does not apply) needs no user confirmation: record the skip and its
  one-line reason in the phase artifact and the session's own state carrier (modules 19/34; the
  state file on `FILE_CAPABLE` hosts, the in-conversation carrier on confirmed `READ_ONLY` hosts),
  then open the next phase directly.
  Never emit a decision prompt for a skip the model can decide.
- Use `FAILURE` only after repeated protocol breach.

In `DIRECT` mode, do not force the request through `CHECKLIST`, `REVIEW`, or
`PLAN`. Follow the direct-mode safety and verification rules instead.

## Drift control

Before every response, validate:

1. What is the current phase?
2. What output template is allowed in this phase?
3. Are all prerequisites satisfied?
4. Is the user asking for an action from a later phase?

If any answer prevents compliant progress, output only the valid current-phase template.
